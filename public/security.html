Eye Drop Tracker

Security

Last updated 6 November 2026

Eye Drop Tracker has no server that holds data, no accounts and no database. Patient information stays on the clinic's computers, in the clinic's own medical record system and on the patient's phone. The software is designed so that it is not sent to us, and we keep no copy. This page is our public description of the software, the information it handles and its safeguards, for clinics, privacy officers and security reviewers.

Safeguards in the website and app

  • A strict content security policy lets the site load code and connect only to itself. No third-party scripts, fonts, analytics or advertising.
  • HTTPS only, with HTTP Strict Transport Security. The site cannot be framed by other sites, and sends no referrer to other sites.
  • No cookies. Patient details use per-tab session storage, cleared after 30 minutes idle, including in reopened tabs.
  • Patient-facing links carry no direct identifiers, and a check code stops damaged or mistyped links from opening.
  • The phone app schedules reminders on the phone itself and can hide drug names on the lock screen.

Safeguards in the Oscar extension

  • By default, Chrome permissions are limited to the open tab when the clinician asks (activeTab), with no standing access to any website.
  • A clinic may allow an optional Eye drops button on its encounters. The extension can ask for this only on the clinic's own Oscar address, fixed in the clinic's copy, and keeps that access until it is removed. The button reads nothing and makes no requests until clicked, and clicks made by scripts are ignored.
  • It talks only to the clinic's Oscar, using the clinician's own login and session, and to eyedroptracker.com in the same browser. The site address is fixed when the extension is built.
  • Writes to the chart need a real click, go only to the patient the plan came from, stop if another clinician has signed in, are made once per plan, and contain only text the extension builds from a valid plan.
  • Clicks made by scripts on a page are ignored. Chart text is shown as text, so markup in a chart cannot run.
  • All code is in the package. Nothing is downloaded and run later.
  • Anyone who can publish a release must sign a confidentiality undertaking and use multi-factor authentication on every account involved.

Testing

Every release runs 62 unit tests, an end-to-end test of the extension with a stand-in Oscar, and a security suite of 18 checks. The suite tries to run hostile markup from every chart field, message the extension from web pages, press its buttons with scripts, forge chart writes, write free text, write to the wrong patient or under the wrong clinician, repeat writes, overload imports and leave data behind. It also records every network request and confirms each one goes only to Oscar or Eye Drop Tracker, with no patient details in any address. The source code is public on GitHub for independent review.

Incidents

If we learn of a flaw or event that could expose patient information, we act within one business day to contain it and release a fix. We tell clinics at the first reasonable opportunity: by email to every clinic on our clinic contact list, by a notice on this website and the Chrome Web Store listing, and by a notice in the app. We record what happened and what we did, and keep that record for at least 24 months. Clinics then meet their own duties to patients and their commissioner, and we help with any facts we have.

Reporting a vulnerability

Email eyedroptracker@gmail.com with "Security" in the subject line. Please describe the problem and how to reproduce it, and do not include real patient information. We reply to security reports within two business days and keep you informed until the problem is fixed.

We will not pursue anyone who reports in good faith, tests only against their own installs or a demo system, does not access or change other people's data, and gives us reasonable time to fix the problem before publishing. Our contact details for researchers are also in security.txt.

Requests from clinics

Clinics can ask for a privacy impact assessment and threat risk assessment template completed for Eye Drop Tracker, the test results for a release, or a countersigned copy of the clinic terms.
